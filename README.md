# dsh-workspace-focus-enhancer

dsh工作区专注增强——让 DeepSeek Harness 侧边栏的工作区列表始终围绕「你正在干的事」组织。

> **一句话介绍**：正在干活的工作区自动排到最前面、一键图钉置顶、点开一个自动收起其他、当前工作区高亮、会话状态一目了然（等你回答 / 异常中断 / 进行中 / 完成未读）、会话收藏。

**当前适配目标与最低版本：DeepSeek Harness `0.2.2-rc.5`。本地版本为 `0.2.0`，尚未发布。** 最低版本声明不是对未来 DSH 版本的兼容保证；本轮验证范围与结果见后文。DSH 处于快速迭代阶段，升级后应重新回归，若插件失效，欢迎[提 Issue](https://github.com/superdadhobo/dsh-workspace-focus-enhancer/issues)。

## 0.2.0 适配 DSH 0.2.2-rc.5

本轮针对实际安装的 **DSH 0.2.2-rc.5**（`release 0.2.2-rc.5`，commit `3f85d88`）逐项核对并升级；上一轮目标为 `0.2.2-rc.1`。

- **不再依赖 Harness 的私有 Client 模块**。设置卡片原来 `require('@deepseek-ai/dsh-client-ui-primitives')` 与 `@deepseek-ai/dsh-client-store`。官方文档明确说明这两者是内部实现模块、导出随时可能变化，且缺少某个导出会让整张卡片静默消失（原实现正是以 `primitives.Switch` 存在与否作为整卡开关）。现在卡片自带 `role="switch"` 开关、状态标签与折叠分组，尺寸/焦点环/`aria-checked` 语义对齐原生控件，只读取宿主 `--dsw-alias-*` 主题变量；模块请求只剩基线 `react` 与 `react/jsx-runtime`。已在真实 rc.5 服务端取回打包产物核对：`module requests: ["react","react/jsx-runtime"]`，无任何 `@deepseek-ai/*` 请求。
- **窗口区域显式声明**（rc.1→rc.5 升级项）。macOS 桌面版现在只对 `data-window-drag` / `data-window-drag-controls` 区域内的控件自动排除拖拽；插件追加到 `body` 的收藏菜单已补 `data-window-drag-exclude` 与 `-webkit-app-region: no-drag`，菜单按钮可正常点击而不会拖动窗口。
- **优先使用稳定锚点**。侧栏标题行改为优先匹配宿主新增的 `data-sidebar-workspace-header` 属性，CSS Module 哈希类名仅作旧宿主回退，构建重命名不再让收藏按钮失去落点。
- **补全显示资源**。新增 `icon.svg`（36×36、纯几何、无脚本/样式/动画，841 字节）并导出 `./icon`；`locale/*.json` 导出改为标准 `./locale/*.json`；中英文 `meta.title` / `meta.description` 按本轮实际能力重写。
- **版本与引擎声明**升级到 `0.2.0` / `engines.dsh >= 0.2.2-rc.5`。

兼容性核对结论（Host 侧全部仍成立）：`workspaceRegistry` 的 `list/get/insertBefore/archivedSessionIds`、`webServer.register`、`connection.requestRejection`、`agents.get/list`、`sessionQuery`、`sessionProjections`；事件 `domain/changed`、`api-session/status|error|removed`、`session/event`、`subagent/start|end`（含 `runId`/`parentSessionId`/`stopReason`/`lastAssistantMessage`）。Client 侧：`window.__ModuleLoader__.load` 工厂格式、`ctx.slots.inject/register/entries/subscribe`、`plugins.bundle.config`（keyed）槽位、`dsh.workspace.view.v5` 持久化键、`sidebar.workspaces` 与 `sidebar.session.row.leading` 槽位、以及 `_sectionHeader`/`projectText`/`folder`/`groupSection` 等 DOM 锚点均存在。升级指南 `v0.2.2-rc.1` 至 `v0.2.2-rc.4` 各条已逐条对照，仅窗口区域一条影响本插件，已修。

本轮验证：自动化 **62 项通过、0 失败**（`ELECTRON_RUN_AS_NODE=1 "$DSH_NODE_EXECUTABLE" --test test/*.test.js`），含 2 项真实 DSH 集成测试；新增回归守卫断言 `client.js` 不含任何 `@deepseek-ai/*` 的 `require`。渲染页实测使用真实 rc.5 Host（私有 `DSH_HOME`）+ Chromium headless：侧栏收藏按钮、4 个图钉、8 格状态 SVG、当前工作区框选均正常；设置卡片 5 个开关（展开后 8 个）、轨道 36×20、点击可写回 Host、深色主题色值正确、图标正常显示。

## 0.1.12 本地适配修复

- **适配 DSH `0.2.2-rc.1` 的真实树形行结构**：托盘每层只移动一次 12px；按行真正所属的托盘收回原生层级缩进，保留原生基础内边距，不依赖 HoverCard 包了几层。工作区、会话与「显示更多」使用同一层级规则。
- **迁移会话读取接口**：通过原生 `sessionQuery` 的非激活 observation 读取 live / cold 会话，使用 wire 问题投影和当前日志恢复等待；不再调用已弃用的 registry `stateOf` 和 Session `snapshotEvents`，显示状态不会启动智能体。
- **完成不等于停止**：只有本轮真正完成且有可见回复才产生未读；取消、被阻塞、失败、无回复和被中断的输出不冒充新回复。子智能体的运行、等待、错误与完成统一归因到根会话，子会话卸载后不丢失根提醒。
- **状态缺失明确提示**：原生状态读取或投影不可用时保留最后可靠信息并显示部分读取失败，恢复后自动重试；不会用空状态假装「已经没事了」。完整逻辑会话源已删除时，退休它留下的等待和标题；批末再次核对读取期间发生的变化。
- **多页面阅读互不覆盖**：每个页面独立续租阅读状态，后台或关闭的页面停止声明「正在读」。任一可见页面已读后，其它页面对齐；原有置顶、收藏和八项设置的保存格式不变。
- **新完成必须经宿主确认**：原生「停下」圆点不能证明有新回复，取消和无回复不会先闪绿勾再退回。正常新完成通常在下一轮查询（约 2 秒内）确认后显示；断线时保留已有确认提醒，不猜测新的完成。新的运行轮次会使旧确认失效，旧查询响应不能复活它。
- **收藏导航不代持主视图**：按原生服务 owner 执行打开动作，而不是借来的消费方上下文；由原生服务负责替换和释放主视图引用，避免收藏导航占住后续「新建会话」。
- **收藏沿用原生规则**：空白、未命名会话显示原生名称而非 UUID；归档收藏保留名单，但先提示取消归档再查看，数据尚未确认时不绕过归档保护。保存和打开失败显示就近反馈。
- **交互与收尾**：直属会话优先时的键盘焦点顺序跟随视觉顺序，隐藏或 inert 控件不拦住退出；服务单独重载会重新绑定，卸载会归还原生节点、样式和订阅，宿主等待已开始的保存/排序/查询收尾。

以上是本轮修复范围，不表示所有未来版本、所有外部 provider 或辅助技术组合已经验收。历史修复说明保留如下。

## 0.1.11 修复

- **会话行补上「正在工作」和「等你回答」**：rc.2 的侧栏只在会话行自己那一轮在跑、或等你回答时才画一个圆点，看起来像是"只有跑起来的会话才有状态"。现在主机状态接口多报两份逐会话清单（`runningSessions`、`waitingSessions`，子智能体折算到发起它的会话），加上页面自己的实时状态表，任意一端都能在行首画出完整状态：橙色问号＝等你回答、红色感叹号＝异常中断、绿色转圈＝正在工作、绿色对勾＝完成未读。页面自己已经画了圆点的行，插件只改颜色和形状，绝不补第二个标记。
- **会话行与工作区不再各说各话**：会话把活交给子智能体后自己停下时，页面只看到"这一轮结束了"，于是给会话行画完成点，而上面的工作区还在转圈。现在行首跟随工作区——子在跑，父会话行也显示绿色转圈；这一轮确实失败了，才显示红标。
- **「等你回答」不再漏报**：rc.2 的持久化问题投影只记录带超时的提问（timed 变体），标准配置里那个阻塞式 `ask_user_question` 完全不在其中，于是主机一直以为会话只是在跑。现在主机直接从会话事件与会话日志两条路认这件事：事件流实时开关，进程重启后则从「本轮还在进行」的日志里补读，收起的 Workspace 也能正确显示橙色。
- **四个状态的优先级与工作区一致**：等你回答 → 异常中断 → 正在工作 → 完成未读，展开的工作区里看一眼行首，就知道上面那只文件夹为什么是那个颜色。

## 0.1.9 优化

- **工作区改用「会填充的文件夹」，会话图形保持不变**：以前工作区和会话共用同一套图形（橙问号 / 红感叹号 / 绿转圈 / 绿对勾），两列虽然对得上，但工作区本身是个装东西的容器，用一排小符号去说状态反而浪费。现在两列各说各的：**颜色还是同一套**（绿＝顺利、橙＝等你、红＝出错），**图形和动效分开**——工作区是一只会被填满的文件夹，会话行继续用原来的圆点、问号、感叹号和对勾。
- **文件夹轮廓和官方一模一样**：直接沿用官方空闲时那个文件夹的路径与 1 像素线宽，同一个 16 像素画布。所以有状态的行和空闲行是同一张图，只是内部被填了色；宽度、名称位置都不动，侧边栏同样不变宽。
- **四种状态各有各的画法**：
  - 🟢 工作中：像**贪吃蛇**在文件夹轮廓里绕圈——从左下角进场往右跑，沿右边上去、从上面往回、再从左边下来，一圈接一圈不停；
  - 🟠 等你回答：下面一排橙色方块**稳稳亮着**，上面一排**一明一暗地闪**，表示停在这里等你；
  - 🔴 出错：文件夹里排成两排的红色方块像一堵墙，整排一起**散落掉出**、一块不剩，随后重新砌好、循环往复；
  - 🟢 完成未读：八个小方块**全部实心、完全静止**——唯一不动的那一个，正好代表"已经结束"。
- **看不懂动效也不会误判**：系统开了「减少动态效果」时自动换成静止画面——绿色停在填了一半、橙色停在中间四格、红色保持亮着，四种状态照样分得清。
- **开关名称跟着改**：控制面板里原来的「橙色问号 / 红色感叹号 / 旋转圈与绿色对勾」已改成工作区填充的说法，避免指向不存在的图形。

## 0.1.8 优化

- **状态图标顶替文件夹图标，不再另占一列**：以前工作区前面是文件夹图标，后面还挂一个状态徽标，一行里挤着两个图形，名称被推得往右偏，整列对不齐。现在有状态时，图标**直接顶替**文件夹图标占住同一个位置，宽度一个像素不差，名称回到和空闲行一模一样的位置；空闲时照旧显示官方的文件夹图标。侧边栏因此完全没有变宽。
- **问号、感叹号、对勾都带上和收藏星标一样的外描边**：星标本来就有一圈比本体深一档的外沿（浅色主题深 62%、暗色主题深 82%），三个静态图形此前是光秃秃的，和星标摆在一起像两套画风。现在它们各自套一层同色加深的描边，同一列里扫一眼过去是一家人。
- **鼠标悬停时状态图标不会被清空**：官方侧栏在鼠标移上去时会把文件夹图标换成一个小箭头。以前状态徽标和文件夹图标各占各的位置，悬停互不影响；现在两者共用一个位置，插件让状态图标优先留在原地，箭头不再出现——状态比箭头重要，而行照样能点。

## 0.1.7 修复

- **工作区卡片上的收藏星标挪到左边**：以前会话被折叠后，它的星标浮到工作区卡片上是画在名称**右边**的，和会话行里「星标在名称前」的位置对不上，同一个收藏在两处长得像两个东西。现在卡片上的星标也放在名称**左边**，与会话行一致；多个收藏仍是 ★ 加数字。
- 星标排在名称之前，与会话行一致：顺序是「★ 数量 → 名称」。

## 0.1.6 修复

- **会话里的子智能体还在干活，工作区却显示成完成**：官方侧栏的会话行其实知道"我派的子智能体还在跑"（鼠标悬停会写"1 个子智能体运行中"），并画绿色转圈；但工作区卡片只看会话自己的那一轮，会话把活外包给子智能体后自己 parked 着，卡片就判成"空闲"，然后落到"完成未读"，于是出现"下面在转圈、上面却是绿对勾"。
  现在工作区状态图标会把子智能体的运行状态算到发起它的会话头上：子智能体在跑，工作区就是绿色转圈；全部停下，才回到空闲或完成未读。子智能体有独立的会话日志，不属于任何工作区，所以只能顺着父会话归位。
- **收起的工作区有时什么状态都不显示**：同一条原因。工作区自己那一轮早已结束，主机上报的"正在工作"列表里就没有它，收起后没有任何标记可上浮，卡片干净得像没事发生；这才是"点开能看到转圈、收起后一片空白"的由来。现在无论展开还是收起，状态图标都按同一条链路算出来。

## 0.1.5 优化

- **会话行状态改用同一套图形语言**：以前会话行只有不同颜色的圆点，工作区却是橙问号 / 红感叹号 / 绿转圈 / 绿对勾，同一件事在两列里长得不一样。现在会话行也画这一套小图形——橙色问号＝等你回答、红色感叹号＝异常中断、绿色对勾＝完成未读，一眼就能对上。（工作区后来改成文件夹填充，会话行保持这一套小图形不变。）
- **进行中改为绿色转圈**：会话在跑时的转圈原本是官方给的灰色（看起来像"什么也没发生"），现在与工作区同色，同一个任务从工作区到会话行是同一个绿色。
- 空闲状态保留官方原本的浅灰圆点：工作区空闲时不显示任何标记，会话行若也留空会破坏整列的左侧对齐节奏。

## 0.1.4 优化

- **树形视图下直属会话排在上方**：按树结构排列时，父工作区自己的会话优先排在子工作区上方，避免最下方的会话紧挨着最后一个子工作区、被误看成是子工作区内会话的问题。插件设置页提供独立开关「树形下直属会话排在上方」，默认开启。
- **多级工作区微阶梯浅色盘（避免嵌套变暗）**：重构展开托盘样式为「大托盘垫小托盘」，严格控制灰度上限并增加细腻内边框，彻底解决多层嵌套展开时半透明背景层层叠加、导致底色过黑的问题；同时提亮未展开文件夹图标线条轮廓，无论嵌套几层都能一眼分清文件夹与会话。

## 0.1.3 修复

- **工作区有红叹号、展开后却没有一个会话行带状态**：官方侧栏只在自己"认得出状态"时才画会话行首的圆点（在跑、等你回答、刚跑完未读）。会话跑挂之后，官方认为它已是空闲，把那个位置留空；本插件原本只给官方圆点换颜色，遇上"根本没有圆点"就无从下手，红点自然画不出来。现在由插件在官方预留的那个位置补一个同尺寸、同色系的圆点：中断的会话红点、跨端未读的会话绿点；官方自己画了圆点的行不会被重复标记。点开该会话，红点消失。
- 这次修正同时补上了 0.1.2「跨端绿点」的最后一环：对面端跑完、本页仍显示空闲的会话，原本没有圆点可染绿，现在由插件补画。

## 0.1.2 修复

- **跨端绿点缺失**：完成未读的状态此前只有"本页面亲眼看到会话跑完"才会在会话行亮绿点；在另一端（如手机 web 端）只能看到工作区绿勾、会话行圆点不亮。现在会话行圆点以主机共享账本为准双向对齐：账本说未读，任何端的会话行都亮绿点。
- **跨端已读不同步**：此前在 web 端点开已完成会话后，桌面端的绿勾仍残留（页面私有记录无法被另一端清除）。现在主机账本对"完成未读"有最终裁决权：任一端点开，其他端的绿勾与绿点在一个轮询周期（约 2 秒）内一起消失。主机不可达或账本比本页记录旧时，仍信本页，绿标不会闪烁丢失。

## 0.1.1 修复

- 修复受信网页请求被错误拒绝为 403，声明原生认证依赖，并保留完整请求供原生检查。
- 状态查询明确只接受 GET；认证异常不绕过检查。状态读取失败会在详情页显示原因，恢复后自动清除提示。
- 设置、置顶、收藏与状态图标通过独立数据的回归测试；不改写现有数据格式。

## 功能特性

1. **工作区自动排序**：工作区进入工作状态时自动靠前；它的上级工作区也会前移，让树形视图收起时仍能看到正在工作的分支。
   - 同时兼容「按工作区」平铺和「按工作区树」。只向上提升必要的父级，不把同一目录下的空闲子工作区整组捎带到前面。
   - 新建工作区、移动会话及会话开始或结束时自动重新整理；状态查询也会检查遗漏的变化，相同顺序不会反复写盘。
2. **工作区置顶**：鼠标悬停在工作区卡片上时显示图钉 📌 按钮，点击即可永久固定置顶，谁也挤不掉它。
3. **分层排序**：
   - 第一梯队：用户手动固定置顶的工作区（按图钉顺序排列）；
   - 第二梯队：当前正在干活的工作区（按最新动工时间先后排列）；
   - 第三梯队：普通空闲工作区。
   - **工作区内会话**沿用官方侧栏自己的排序（「最近更新」或你手动拖出的顺序），本插件不做改动。
4. **工作区状态：一只会被填满的文件夹**：有状态时，**顶替**工作区前面的文件夹图标（同一个位置、同样的宽度、同样的轮廓，名称位置不变），按紧急程度取第一优先：
   - 🟠 橙色（下排常亮、上排闪烁）：有会话在等你回答或批准；
   - 🔴 红色（两排方块像墙一样散落掉出、再重新砌好）：有会话异常中断，点开该会话后自动消失；
   - 🟢 绿色小蛇（在文件夹里绕圈跑，从左下角进场）：有会话正在工作；
   - 🟢 八格实心绿（静止不动）：有会话已完成但你还没看；
   - 空闲时不显示，仍用官方原本的文件夹图标。
   - 轮廓与官方文件夹同一路径、同一线宽；四种状态都是“轮廓 + 内部八个小方块”，只是方块怎么动不一样，所以切换状态时图标形状不会变。
   - **颜色与会话行完全同源**：绿色、橙色、红色用的是同一组颜色，两列对同一件事不会各说各话；只有形状与动效分开。
   - 状态有两条来源，同时生效、按行取更紧急的那个：页面自己的实时会话状态表，以及主机接口（2 秒一次）。**仅在树形视图中，上级收起时，子工作区的图标才会上浮到真实的、已收起的最近可见父级**。筛选或搜索隐藏的独立工作区不会把图标挂到其他工作区上。
   - 「完成未读」的实心绿色只在回复确实没看过时出现；在可见页面里看着跑完的不算未读，切走也不会补出一个来。运行中的绿色动效仍表示正在工作，不受未读条件限制。
   - **会话行画同一套状态**：行首依次是橙色问号（等你回答）、红色感叹号（异常中断）、绿色转圈（正在工作）、绿色对勾（完成未读），与工作区的文件夹同色同优先级。中断的红标点开即消失。
   - 会话行与工作区各取所需：官方侧栏画出圆点时插件只改它的颜色和形状（必要时把它从"完成"改回"进行中"，让行与卡片一致）；官方没画（rc.2 的空闲行）时由插件补画，一行始终只有一个标记。
5. **无关工作区自动折叠**：点开一个工作区，其他展开着的自动收起；它的上级目录和子目录不受影响，所以嵌套视图里刚点开的行不会消失。
   - 点击标题展开时，一次提交目标展开和其他分支收起；手动收起标题也使用相同的位置保护。切换期间统一处理列表原生移动动画与浏览器滚动补偿，按最终布局定位。
   - 尽量让刚点击的标题留在原来的可视位置；到达滚动边界时停在最近可达的位置，保证标题可见，不添加空白占位。继续滚动、触摸或点击时立即交还操作。
   - 自动收起的工作区会记住此前「显示更多」的会话数量；手动收起仍沿用页面默认的数量重置。
6. **高亮当前工作区**：把正在看的那个会话所属的工作区**连同它展开的会话一起**框一圈主题色边框；工作区收起时框住那一条，折叠状态下也照样能定位。
7. **会话收藏**：鼠标移到任一会话上，行首出现 ☆，点击即收藏（实心 ★）。
   - 会话露着时，星标画在**会话行**上（文字前，排在状态图标之前）；
   - 工作区折叠、会话被藏时，星标**上浮到工作区卡片**（也在文字前，与会话行同一侧），多个收藏显示 ★ 加数量；父级也折叠时继续逐级上浮；
   - 星标与工作区的状态文件夹、会话行的圆点**互不遮挡**：两者都在文字前，星标排在名称之前，与会话行的顺序一致；
   - 侧边栏「工作区」标题右侧（搜索按钮左边）有 ★ 按钮，点开列出全部收藏，点一条即打开该会话（会话藏在折叠工作区里也能打开）。

### 数据说明

- 置顶名单、排序开关、会话收藏保存在 `~/.dsh/storages/` 下的 `workspace-pins.json`、`workspace-order-settings.json`、`workspace-favorites.json`，换浏览器、清缓存后自动从主机读取。
- 卸载插件不会删除这三个文件；想彻底清掉再手动删除即可。
- `DSH_HOME` 已设置时使用它的 `storages` 目录，不固定写入默认主目录。
- 运行和等待可从原生逻辑会话重读；异常与完成未读仍是宿主本进程的共享提醒，未新增跨宿主重启的持久化账本。归档收藏保留数据，是否参与工作区状态聚合沿用原策略。
- 页面每 5 秒续租自己的阅读状态，租约为 18 秒；页面进入后台或卸载即报告不在读，断开后未续租的状态自动过期。

## 安全说明

- 所有读取和写入接口都交给 DSH 原生 `connection` 服务检查登录、受信域名和请求来源。已登录的本机、局域网和受信反代网页使用相同规则，不再添加额外的“只允许本机”判断。
- 未登录、错误域名和跨站来源仍由 DSH 拒绝；插件不设置受信域名、不修改原生认证，也不依赖双端切换插件。
- `connection` 是必需依赖；认证服务缺失时插件不会绕过认证启动。
- 请求体只接受 `application/json`（与官方 RPC 桥一致），不认 `text/plain` 等可绕过预检的内容类型。
- 名单文件以临时文件 + 改名的方式原子落盘，权限 0600，与存储后端的其他文件一致。

## English

**dsh-workspace-focus-enhancer** enhances the DeepSeek Harness web sidebar:

- **Auto-order**: workspaces with running sessions move to the front; ancestors move up so busy branches stay visible in the collapsed tree view.
- **Pin**: hover a workspace card and click 📌 to pin it to the top, permanently.
- **Three-tier ordering**: pinned → busy (newest first) → idle.
- **Status badges**: 🟠 waiting for you · 🔴 interrupted · 🟢 running · ✅ done unread — badges float up to the nearest visible ancestor in tree view; interrupted sessions get a red dot on their row too.
- **Session-row states**: every row carries its own mark — 🟠 waiting on you · 🔴 interrupted · 🟢 running · ✅ done unread — drawn in the leading cell the page leaves empty. Where the page does paint a dot, the plugin recolours it instead, so a row never carries two marks.
- **Auto-collapse**: opening a workspace collapses unrelated expanded ones, with scroll position preserved.
- **Current highlight**: the workspace owning the session you're viewing gets a themed outline, even when collapsed.
- **Favorites**: star sessions; stars float up to collapsed workspace cards with counts, and a ★ button next to the sidebar title lists them all.

All eight switches are individually toggleable in the plugin's detail page (sidebar → Plugins).

### Install

1. Open the **Plugins** page in the DSH sidebar.
2. Click **Add plugin**, then enter either:
   - the npm package name: `dsh-workspace-focus-enhancer`, or
   - the GitHub repo: `https://github.com/superdadhobo/dsh-workspace-focus-enhancer`
3. Click **Install**, then **Enable**. DSH applies the plugin through its native loader; reload the page to confirm the updated client.

The local `0.2.0` release targets DeepSeek Harness `0.2.2-rc.5` and requires at least that version. It has not been published to npm or GitHub yet. Automated and isolated native checks are separate from UI walkthroughs and human acceptance; the minimum-version declaration is not a compatibility certificate for future releases. If a DSH upgrade breaks something, please [open an issue](https://github.com/superdadhobo/dsh-workspace-focus-enhancer/issues).
